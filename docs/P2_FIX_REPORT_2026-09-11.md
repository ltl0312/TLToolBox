## 11 · M5 / M8 / M10 与全部 L 级项

### M5 · 原生监听表二段式调用重试

`scanner::enumerate_table`（新通用骨架）：统一「尺寸探测 → 分配缓冲 → 枚举」三步，
对 `ERROR_INSUFFICIENT_BUFFER(122)` 循环重试至多 5 次（每次按 API 回填的新尺寸重新分配），
其余非零错误立即上抛。TCP / UDP 两条路径收敛到同一实现，消除"表在两步之间增大 →
扫描偶发失败且 UI 无结果"。空表（首轮即返回 0）语义保留。

### M8 · 更新请求边界收紧

- **响应体上限**：新增 `update::MAX_BODY_BYTES`（1 MiB）；`read_body` 在每次分块读取
  **之前**经 `exceeds_body_limit`（`saturating_add`，杜绝溢出 panic）判定，超限立即中止
  并按"无版本信息"处理（`Ok(None)`，绝不误报）。上限值以编译期 `const` 断言锁定。
- **重定向策略**：请求创建后即设置 `WINHTTP_OPTION_REDIRECT_POLICY_NEVER`
  （`REDIRECT_POLICY_VALUE` 常量 + 离线守卫测试）。设置失败仅告警不阻断——默认策略
  已禁止 HTTPS→HTTP 降级，残留风险有限，不因加固动作本身让"检查更新"不可用。
  联网回归实测通过（`cargo test -- --ignored update::`）。

### M10 · 卸载失败重试与残留清理

`terminal_logger`：

1. **自动重试**：`stop` 的卸载路径改为 `uninstall_with_retry`——最多 3 次、间隔 150ms，
   覆盖"配置文件被编辑器 / 杀毒进程瞬态占用"这一最常见失败形态；每次失败均 `warn` 留痕。
2. **残留可见**：新增 `last_stop_error()` 与 `needs_repair()`（卸载失败 **或** 运行标志为真
   但注册表片段被外部清理），不再出现"点了没反应、系统悄悄残留"。
3. **手动修复入口**：新增 `force_cleanup_hooks()`——不依赖运行状态与快照，按当前配置重新
   装配全部 Shell 挂载器并逐一卸载（幂等）；同步文件 / 注册表 IO 经 `spawn_blocking` 执行。
   UI 侧「终端日志记录」设置弹窗新增「强制清理钩子」按钮（`force_cleanup_terminal_hooks`
   回调），成败均写审计 + Toast。
4. **装配层审计**：`set_all_modules` 失败路径补写 `[模块开关]` 审计（此前仅 `warn`）；
   进程收尾时 `terminal_logger` 停止失败的审计文案点名残留风险与修复入口。

## 11 附 · M3 / M4②（审计中未分配迭代的中等项）

### M3 · 弹窗黑名单匹配

- **匹配模式（增量、向后兼容）**：关键词支持 `exact:`（全等）/ `prefix:`（前缀）/
  `word:`（ASCII 词边界）三种显式收窄前缀，无前缀仍是既有子串语义——旧配置零迁移。
  `word:Update` 不再命中 `Updated` / `MyUpdateTool` 这类连续词（审计指出的误拦面）。
  解析对多字节字符边界做了防御（`str::get`），中文等无词边界文本文档化为"用子串或 exact:"。
- **动态缓冲（漏拦半边）**：标题先 `GetWindowTextLengthW` 取精确长度；类名无长度 API，
  按 256 起步、命中容量翻倍重查，统一 4096 字符封顶——超长标题尾部的关键词不再丢失。

### M4② · 置顶 stop 超时后双钩子

`stop_impl` 超时分支不再把 `running` 置 `false`：泵线程未退出时保持「停止未完成」语义，
返回错误并**把 `run` 句柄放回 `active` 槽位**（`thread` 以 `take()` 方式取出以便放回），
支持再次停止；Join 任务自身异常同样按"停止未完成"处理。杜绝"旧钩子仍在生效 + 再次
`start` 安装第二套 `SetWinEventHook` / 计时器"的重复纠偏。

## 12 · `icon_locker` 拓扑指纹真正生效

自动还原（`WM_DISPLAYCHANGE` 触发路径）现在以指纹为闸门：

- 新增纯函数 `profile_matches_topology(saved, current)`：**非空且逐字节相等**才允许还原；
  空指纹视为来源不明、一律不应用。
- 不匹配 → 跳过还原 + Toast（"显示器拓扑与方案不一致，未自动还原"），图标保持现状——
  修复审计指出的"把旧坐标刷到当前桌面、误移动用户图标"。
- 手动还原（`restore_profile`）是用户显式请求，不受此限制。
- 语义澄清（写入了代码文档）：触发即"拓扑已变"，因此还原只在拓扑**回到**方案保存时的
  形态（如外接屏重新插回）时发生——这正是该功能的本意。

## 14 · 线程铁律类型化（部分完成）

新增 `src/thread_rules.rs`：

- `UiThreadToken`：UI 线程令牌，进程内仅可领取一次（`AtomicBool` 登记），`main` 装配期
  在 UI 线程领取，重复声明即装配冲突（硬失败）；
- `UiDeliver<T>`：UI 交付通道，**只能凭令牌构造**——"向 UI 投递"的能力由装配层显式分发；
  其他线程仅获得 `deliver()` 单向上行，通道关闭时归还载荷可降级。

**诚实边界**：②"锁不跨 await"是作用域问题，Rust 类型系统无法表达"持锁期间不得 await"；
③ COM 隔离已由 `spawn_com_thread` + `StaCom`（初始化 / 反初始化配对守卫）在类型层面落实。

**迁移完成（同日追记）**：装配层在领取令牌后安装**进程级规范通道**
`thread_rules::install_ui_deliver`（单泵：Tokio 工作线程消费 FIFO 作业并逐条转发到
`invoke_from_event_loop`，铁律①的执行端收敛为一处）；`main.rs` 全部 **21 处**
`slint::invoke_from_event_loop` 调用点已机械替换为 `thread_rules::deliver_ui(Box::new(..))`
（文档注释中的提及保留）。`deliver_ui` 在通道未安装 / 已关闭时归还作业（`Err(job)`），
不 panic、不静默。剩余收敛点仅 Slint 弹窗组件的属性回调（本就运行在 UI 线程，无需迁移）。

## §6.3 · `deny(unwrap_used, expect_used)` 评估结论

**暂不启用**，理由：

1. 抽样统计全仓 `unwrap` / `expect` 分布：绝大多数位于 `#[cfg(test)]` 与 FFI 句柄包装的
   SAFETY 前置条件中（如"刚创建的句柄必为 Some"），启用后需要一次性引入大量
   `#[allow]` 或重构，改动面与收益不成比例；
2. 项目已通过 CI 的 `clippy -D warnings` 锁住"静默吞错误"类增量（P1 落地），本审计
   第 4 节的"失败静默"反模式已经逐项清理（P1/P2 合计 10 处）；
3. 建议改在**新增代码**的 review 约定中执行，或待 `clippy::unwrap_used` 支持
   "仅对非测试代码生效"的稳定配置后再启用。
