## 1. 桌面图标还原无效

**症状**:拓扑切换后图标没有归位;手动点「还原」后图标瞬间归位,又被系统弹回;
或还原成功但位置仍然不对。

### 1.1 首要排查:桌面右键「自动排列图标」

这是 **80% 以上还原失败的第一元凶**。Windows 在启用「自动排列图标」时,
Explorer 会把所有图标强制吸附到网格,并**吞掉** `IFolderView::SelectAndPositionItems`
的定位结果——程序侧无论如何瞬移都会被立即纠正回网格。

排查步骤:

1. 在桌面空白处**右键** → 依次展开 **查看(V)** → 确认 **「自动排列图标」处于
   *未勾选*状态**;
2. 同时建议保持 **「将图标与网格对齐」** 勾选(可让归位结果稳定吸附网格,
   与自动排列的强制吸附不同,对齐网格不会移动手动定位的图标);
3. 重新点击 ⚙ 齿轮进入「桌面图标布局锁」→ 选中方案 → 「还原」;
4. 若仍被弹回,可尝试:右键桌面 → 刷新,或在任务管理器结束 `explorer.exe` 后
   重新运行(`文件 → 运行新任务 → explorer.exe`)再还原。

> 程序侧约束:自动排列是 Windows 行为限制,TLToolBox 无法从程序侧绕过;
> 还原失败时模块会经事件总线弹出 Toast 提示排查本项(见 ADR-0006)。

### 1.2 方案与当前拓扑不匹配

- **症状**:还原后图标挤在屏幕一角,或多屏之间位置错乱;
- **原因**:布局方案按「显示器拓扑指纹」绑定(如
  `P:0,0,2560x1440|S:-1920,0,1920x1080`)。当前屏幕组合与保存方案时的组合
  不一致时,坐标对不上;
- **排查**:⚙ 弹窗顶部会展示「当前环境指纹」,与方案列表中的指纹比对;
  若确实切到了新拓扑,应针对该拓扑**重新保存一份方案**(不同拓扑独立保存,
  互不串扰,切换后自动还原会命中对应方案)。

### 1.3 还原失败 Toast:「显示器拓扑自动还原失败」

- **原因**:COM 链路失败(Explorer 桌面视图不可用 / 被接管 / 桌面未就绪),
  或尚无已保存方案;
- **排查**:
  1. 确认 Explorer 正常运行(任务栏 / 桌面可见);
  2. 确认已保存至少一份布局方案(⚙ 弹窗列表非空);
  3. 查看当日运行日志 `logs\tltoolbox.YYYY-MM-DD.log`,搜索 `icon_locker`,
     日志会记录具体失败步骤与 HRESULT(如 `FindWindowSW 失败 (HRESULT=0x...)`);
  4. 若日志显示 `CoInitializeEx 返回 RPC_E_CHANGED_MODE`,属正常容错(复用既有
     COM 公寓),不必担心。

### 1.4 自动还原没有触发

- **症状**:拔插屏幕后图标乱跑,但没有任何还原动作;
- **排查**:
  1. ⚙ 弹窗中确认「显示器拓扑变化后自动还原」开关处于**开启**状态
     (对应配置 `icon_locker.auto_restore = true`);
  2. 确认模块卡片开关已**开启**(模块未启动则守护线程未运行);
  3. 连续快速插拔时,1500ms 防抖会持续顺延,请在屏幕稳定后等待约 1.5~2 秒再观察。

## 2. 任务栏图标强缓存刷新

**症状**:程序升级 / 重启后托盘图标仍显示旧图标、出现两个托盘图标、或托盘区域
残留已退出程序的幽灵图标。

### 2.1 先做程序侧检查

- **双托盘图标**:TLToolBox 有单实例守卫(具名互斥),正常不会双开。若出现两个,
  多半是**资源管理器缓存了旧图标**,而非真的开了两个进程——可用任务管理器确认
  只有一个 `tltoolbox.exe`。

### 2.2 刷新 Windows 图标缓存(强缓存刷新)

按顺序尝试,强度递增:

1. **仅刷新托盘区**(最轻):重启资源管理器托盘——
   `设置 → 个性化 → 任务栏`,或直接执行下面第 2 步;
2. **重启资源管理器**:
   ```
   # 任务管理器 → 进程 → Windows 资源管理器 → 右键 → 重新启动
   # 或命令行:
   taskkill /f /im explorer.exe
   explorer.exe
   ```
   重启后托盘区强制重建,旧图标随之清除;
3. **重建图标缓存数据库**(图标本身变形 / 张冠李戴时):
   ```
   # 关闭资源管理器
   taskkill /f /im explorer.exe
   # 删除图标缓存(按需选择,系统会重建)
   del /a /f /q %localappdata%\IconCache.db
   del /a /f /q %localappdata%\Microsoft\Windows\Explorer\iconcache_*.db
   # 重新启动资源管理器
   explorer.exe
   ```
4. **强制刷新 Shell 图标缓存**(无需重启资源管理器的轻量指令):
   ```
   ie4uinit.exe -show
   ```
   或(旧系统)
   ```
   ie4uinit.exe -ClearIconCache
   ```
5. 若以上均无效且仅 TLToolBox 图标异常:确认 `res/app.ico` 内嵌图标为
   16 / 32 / 48 / 256 多尺寸(程序读取 `RT_GROUP_ICON` / `RT_ICON` 资源帧),
   资源缺失时程序会自动降级为系统默认图标——此属正常兜底,不影响功能。

> 提示:TLToolBox 的托盘图标每次启动都从 exe 资源段**重新加载**并渲染,
> 不存在程序内图标缓存;残留旧图标均来自系统 Shell 缓存,按 2.2 刷新即可。

## 3. 端口猎手权限限制 (UIPI)

**症状**:点击「一键释放」后 Toast 提示
「需要管理员权限,请通过顶部盾牌提权运行」;或直接失败、进程未被终止。

### 3.1 原因

Windows UIPI(用户界面特权隔离)限制**普通权限进程**对**更高完整性级别进程**
(以管理员身份运行的服务 / 程序 / 系统进程)执行操作。`TerminateProcess` 对高
完整性目标返回 `ERROR_ACCESS_DENIED`(错误码 5),被模块识别为 UIPI 拦截。

### 3.2 排查与解决

1. **确认目标进程是否值得终止**:被拦截的目标通常是
   - 以管理员身份运行的开发进程(如提权的 Node / Java 服务);
   - Windows 系统服务(如 HTTP.sys 承载的 IIS / WSL2 端口转发);
   - 杀毒 / 监控软件自带的监听端口。
2. **提权运行 TLToolBox**:点击主窗口顶部**盾牌按钮**(或托盘右键菜单 →
   「以管理员身份重启」),程序经 UAC 提权后重启,即可终止高完整性进程;
3. **谨慎操作**:提权后终止进程权限更高,请务必先确认端口占用进程身份
   (弹窗中会展示进程名与 PID),避免误杀系统服务;
4. **仍失败时**:
   - 查看 `logs\port_hunter\port_hunter.log` 的 `KILL` 事件,内有 Win32 错误码;
   - 若错误码为 5(`ERROR_ACCESS_DENIED`),重复步骤 2;
   - 若错误码为 5 之外的其它码(如 87 参数错误 / 6 句柄无效),多为目标进程
     已退出(端口已被释放),重新扫描即可。

### 3.3 相关:端口显示不全(四重降噪)

`show_system_ports = false`(默认)时,模块会过滤:非 LISTEN 状态、IANA 动态高位
端口、Session 0 服务进程、系统服务黑名单四类条目。若你确实需要看到被过滤的
系统 / 动态端口,在 ⚙ 弹窗中勾选「显示系统服务与动态高位端口」即可
(对应 `[port_hunter] show_system_ports = true`)。

## 4. 弹窗拦截不生效或误伤

**症状**:广告弹窗没被拦下;或正常窗口(如软件更新提示)被误关。

### 4.1 高特权弹窗拦不下来

- **原因**:UIPI 限制——以管理员身份运行的流氓安装包 / 更新器弹窗,普通权限
  进程无法向其投递 `WM_CLOSE`;
- **解决**:点击顶部盾牌按钮提权运行,获得 100% 拦截能力(拦截日志中这类弹窗
  通常表现为「捕获目标弹窗后关闭失败」)。

### 4.2 黑名单规则不生效

- 规则为「窗口标题 / 类名**子串匹配、忽略大小写**」,中文关键词逐字生效;
- 新增 / 删除规则后**即时热重载**(COW 快照),无需重启程序;
- 若仍不生效:确认关键词确实是弹窗**标题或类名**的子串(可先放宽关键词测试);
- 默认黑名单含 `广告` / `Flash Helper Service` / `Update Notice` / `推广弹窗`,
  通过 ⚙ 弹窗自由增删。

### 4.3 误伤正常窗口

- 弹窗拦截是「窗口标题 / 类名关键词」匹配的启发式拦截,可能误伤命名相似的窗口;
- **解决**:在 ⚙ 弹窗中**删除误伤的规则关键词**,或换用更精确的关键词;
- 若需要留证,`logs\popup_screenshots\` 目录保存了被拦截弹窗的截图留痕
  (PrintWindow 捕获,PNG),可据此校准规则。

## 5. 终端日志不记录或记录不全

**症状**:CMD / PowerShell / Bash 中的输入没有被记录;或部分命令缺失。

### 5.1 先确认基础状态

1. 模块卡片开关已开启;
2. 日志目录存在且可写(默认 `logs\terminals\<终端类型>\`,可在 ⚙ 弹窗查看
   绝对路径,并点击「在文件资源管理器中打开」);
3. 检查 `logs\tltoolbox.YYYY-MM-DD.log` 中 `terminal_logger` 相关的错误。

### 5.2 CMD 记录不全(常见)

- **「/c 护栏」会跳过构建子进程**:AutoRun 捕获脚本用 `findstr /I /C:"/c"`
  探测 `%CMDCMDLINE%`,当命令行包含 `/c`(如 `cargo`、`git`、`npm` 等构建工具
  派生的后台子进程)时**瞬时跳过**,防止管道中继导致终端假死 / 编译挂起——
  这是有意设计;
- **新开 CMD 窗口未生效**:AutoRun 挂载后需**新开** CMD 窗口才会加载
  (已打开的窗口不重读注册表 AutoRun);
- **安全软件拦截 AutoRun**:部分杀软会拦截注册表
  `HKCU\...\Command Processor\AutoRun` 写入,可尝试先关闭杀软的注册表防护再启用。

### 5.3 PowerShell / Bash 记录不全

- PowerShell 通过挂载静默转录流 + 代理 `prompt` 捕获 `$LASTEXITCODE`;
  Bash 通过 `PROMPT_COMMAND` 与历史行解析。若你手动修改过
  `$PROFILE` / `~/.bashrc`,可能覆盖或移除 TLToolBox 锚点块;
- 检查 Shell 配置文件中是否存在 `# >>> TLToolBox TAG >>>` 注释块
  (锚点引擎写入的标记);被删除时重新启用一次模块即可原位重建,卸载时会逐字节
  还原,不破坏原生配置。

### 5.4 日志按天滚动与保留

- 终端会话日志默认保留 **14 天**(`terminal_log_retention_days`,可配置,`0` =
  立即清理全部过期日志);
- 过期清理由模块的守护任务自动执行;若目录占用巨大,检查是否有长驻会话
  (未退出的终端持续追加 `session.log`)。

## 6. 配置文件解析失败或改动不生效

**症状**:手工编辑 `config\tltoolbox.toml` 后重启不生效;或启动后配置被重置。

### 6.1 先确认改的是「对的文件」

- 配置路径为 `exe 同级目录\config\tltoolbox.toml`,**以可执行文件所在目录绝对
  锚定**,与当前工作目录(CWD)无关——经注册表自启(CWD 为
  `C:\Windows\System32`)时也不会找错文件;
- 如果你复制了程序目录,请确认改的是**正在运行的那个 exe** 旁边的配置文件
  (绿色便携版多份拷贝易混淆)。

### 6.2 改动不生效

- **模块开关类配置**(`enabled` / `auto_restore` 等)由 UI / 托盘切换后**自动
  持久化**,手工编辑后若模块已启动,部分字段不会热读——重启程序生效;
- **弹窗黑名单**例外:运行期修改 `popup_blacklist` 后需经模块 `update_rules`
  热更新或重启应用(模块不会自动重读文件);
- 修改后**保存格式必须合法 TOML**:解析失败时程序返回 `Parse` 错误并
  **原样保留你的文件**(绝不静默覆盖),但本次以内存默认值运行——修复 TOML
  语法后重启即可。

### 6.3 配置被重置 / 丢失

- 程序采用「临时文件 + 原子 rename」写盘,崩溃不会产生半截损坏文件;
- 若你观察到处处被重置,检查是否同时运行了多个 TLToolBox 实例(单实例守卫
  只保护同会话;不同用户会话各有一个实例时,后者会覆盖配置——多用户共机场景
  注意区分)。

### 6.4 保存时报共享冲突

- 杀毒软件 / 索引器瞬态占用配置文件时,程序会自动退避 20ms 重试 3 次
  (`ERROR_SHARING_VIOLATION` 防御),通常无感;
- 若频繁失败,可把程序目录加入杀软白名单。

## 7. 开机自启失效或重复启动

### 7.1 自启不生效

1. 确认主窗口顶部「开机自启」开关处于开启状态;
2. 自启写入的是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
   (免提权)。可用注册表编辑器确认存在 `TLToolBox` 值且指向当前 exe 路径;
3. 若注册表存在但登录未启动:确认登录的是**同一 Windows 用户**(Run 键按用户
   隔离);
4. 启动装配层会自动收敛配置与注册表状态(配置开而缺失 → 补写;关而残留 →
   删除)。若被第三方清理工具删掉 Run 键,重新开一次开关即可。

### 7.2 重复启动 / 双托盘图标

- 单实例守卫基于会话级具名互斥;重复双击或自启拉起时,第二实例会广播自定义
  唤醒消息让既有窗口前置,自身立即退出;
- 若出现两个托盘图标,多半是 [任务栏图标强缓存刷新](#2-任务栏图标强缓存刷新)
  问题(资源管理器缓存),先按 2.2 刷新;
- 确认没有残留僵尸进程:任务管理器搜索 `tltoolbox.exe`,正常应只有一个
  (提权重启瞬间会短暂出现两个——旧实例带 `--restart-as-admin` 握手退出)。

## 8. 杀软误报与 SmartScreen 未知发布者

**症状**:首次运行弹出 SmartScreen「未知发布者」;杀软隔离或拦截 exe。

### 8.1 说明

- 项目未作付费商业代码签名(数字证书需企业资质),SmartScreen 对未签名程序
  提示「未知发布者」属正常现象;
- 项目**不含任何网络请求 / 遥测 / 注入代码**(弹窗拦截用系统级事件钩子,
  图标锁用 Shell COM,均为公开 API),可自行编译源码核对后放行;
- 防杀软误报建议:将程序目录加入杀软白名单 / 排除项。

### 8.2 区分「误报」与「真威胁」

- 核对文件哈希:发布包随附 `.sha256` 校验和,与官方 Releases 一致即为正版;
- 观察拦截详情:若指向 `VirtualAllocEx` / `ReadProcessMemory` / 写注册表
  Run 键等行为,可放心(见 ADR-0006,本项目图标锁明确禁用内存注入)。

## 9. 检查更新失败

**症状**:「检查更新」报错或无响应。

- **离线环境**:本项目更新检查走 WinHttp 请求
  `https://api.github.com/repos/ltl0312/TLToolBox/releases/latest`(连接 / 发送 /
  接收各 8 秒超时)。完全离线的保密开发机上该请求必然失败——**不影响任何本地
  功能**,可忽略;
- **GitHub 网络受限**(中国大陆网络常见):`api.github.com` 可能超时或被重置,
  可手动访问 `https://github.com/ltl0312/TLToolBox/releases/latest` 确认版本;
- 失败仅为提示,不阻断程序运行;成功时也**不自动下载安装**(仅提示新版本),
  请从 Releases 手动下载并核对 SHA256。

| 端口猎手明细 | `logs\port_hunter\port_hunter.log` | SCAN / SEARCH / KILL 事件明细 |

> 所有路径均可通过对应模块的 ⚙ 弹窗自定义(见 `config/tltoolbox.example.toml`
> 中的 `terminal_log_dir` / `app_log_dir` / `popup_screenshot_dir` /
> `[port_hunter].log_dir`)。
