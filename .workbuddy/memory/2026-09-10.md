### 关键结果
1. **S1 修复 + 新发现 S1-b（重要！）**：补 `WINHTTP_QUERY_FLAG_NUMBER` 只是修了一半。
   `WinHttpSendRequest` 的 `dwHeadersLength` 语义是"头块字符数"，而 windows-rs 把 `Some(&[u16])`
   直接映射为 `(ptr, len)`——生产代码传入的 `to_wide_units(..)` 切片**含尾部 NUL**，
   WinHttp 判 `E_INVALIDARG (0x80070057)`，**请求根本发不出去**。实测对比：
   含 NUL(len=61) → E_INVALIDARG；不含 NUL(len=60) → `Send Ok / ReceiveResponse Ok / status=200`。
   修复落点：`update.rs::imp::request_headers()` 统一 `pop() ` 掉终止符。
   → **经验：windows-rs 中凡把 `&[u16]` 交给"带显式长度参数"的 Win32 API，切片必须去掉 NUL 终止符。**
2. **S2**：`kill_process_and_release_port` 入口加无条件闸门 `is_protected_target`（与展示选项解耦，
   镜像名用终止时刻实时查询，顺带缓解 S3）；新增 `PortError::ProtectedProcess`；UI 侧系统行改渲染
   「系统进程」静态标签（`PortEntryItem.protected`），界面禁用与入口拒绝同源。
3. **S4**：`run_pump` 就绪通道改 `Result<isize, String>`，`CreateWindowExW` 失败即回传错误并返回
   （不进消息泵）；新增 `STOP_JOIN_TIMEOUT=2s` + `join_with_timeout`，`Drop` 不再裸 join。
4. **S5**：新增 `src/ffi_guard.rs::guard_ffi`（`catch_unwind` + `AssertUnwindSafe`，兜底自身再包一层
   catch_unwind）；6 处 FFI 入口全部包裹（含把 `tray` 消息泵单轮迭代抽成 `pump_once`，覆盖
   muda/tray-icon 第三方窗口过程）。注意 `guard_ffi` 是 `#[must_use]`，丢弃返回值的调用点须写 `let _ =`。

### 测试新增（可复用套路）
